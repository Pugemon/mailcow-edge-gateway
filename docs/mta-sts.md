# MTA-STS

MTA-STS (RFC 8461) сообщает отправляющим серверам: «доставляйте на эти MX только по TLS с валидным
сертификатом». В mailcow он встроен: политику для домена задают в настройках домена в интерфейсе
администратора, nginx mailcow отдаёт её по `https://mta-sts.<домен>/.well-known/mta-sts.txt`.
Через шлюз этот адрес обслуживает reverse proxy (`docs/reverse-proxy.md`).

## Что нужно

- `mta-sts.<домен>` — A/CNAME на шлюз, имя добавлено в proxy host reverse proxy (валидный сертификат
  для этого имени обязателен — отправители проверяют его);
- TXT `_mta-sts.<домен>` с идентификатором политики;
- (рекомендуется) TXT `_smtp._tls.<домен>` для отчётов TLS-RPT.

## На время переезда: testing и оба MX

Пока MX ещё у старого провайдера или только что переключён, политика должна разрешать **оба** MX,
а режим — `testing` (нарушения только попадают в отчёты, доставка не блокируется):

```
version: STSv1
mode: testing
mx: mx.old-provider.example
mx: mail.example.com
max_age: 86400
```

`max_age: 86400` (сутки) — отправители перечитают политику не позже чем через сутки, так что
её можно быстро менять в ходе переезда.

DNS:

```
_mta-sts.example.com.   300  IN  TXT  "v=STSv1; id=<id из mailcow>"
_smtp._tls.example.com. 3600 IN  TXT  "v=TLSRPTv1; rua=mailto:tls-reports@example.com"
```

`id` — до 32 латинских букв и цифр; mailcow показывает его в настройках политики. При **каждом**
изменении политики `id` должен меняться — иначе отправители не перечитают файл.

## Если у старого провайдера уже был MTA-STS

Если домен уже публиковал политику в режиме `enforce` без нового MX, отправители, закэшировавшие её,
откажутся доставлять почту на новый сервер после смены MX — до истечения её `max_age` (бывает неделя
и больше). Поэтому политику с обоими MX (и новым `id`) публикуйте заранее — не позже чем за `max_age`
старой политики до переключения.

## После переключения: enforce

Когда старый MX выведен из записи MX и прошло не меньше `max_age` текущей политики:

```
version: STSv1
mode: enforce
mx: mail.example.com
max_age: 604800
```

и новый `id` в `_mta-sts.<домен>`. `max_age` можно увеличить (например, до 1209600 — 14 дней), когда
конфигурация устоится.

## Проверки

```sh
curl -s https://mta-sts.example.com/.well-known/mta-sts.txt   # политика, Content-Type: text/plain
dig +short TXT _mta-sts.example.com                           # "v=STSv1; id=..."
dig +short TXT _smtp._tls.example.com                         # "v=TLSRPTv1; rua=..."
```

Сертификат на почтовом порту должен быть валиден для имени из `mx:` — проверка
`tools/check-tls.sh mail.example.com` (порт 25, `Verify return code: 0`).
